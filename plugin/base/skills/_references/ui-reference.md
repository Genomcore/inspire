# The UI reference — what the screen layer is measured from

> Shared by [`inspire-bootstrap`](../inspire-bootstrap/SKILL.md) and
> [`inspire-screens`](../inspire-screens/SKILL.md). Read before measuring anything
> into `design-system.md`, `design-tokens.json`, a `layouts/` entry or a
> `## Render` table.

A value in the screen layer is either **decided** — the design system fixes it — or
**observed** in a reference, or **proposed** because nothing held it. The Source
column of every layout row says which, and this file says where the reference comes
from and how it is read.

## Which reference

One reference per vault at a time, chosen in this order:

1. **The one the operator names.** A deployed URL, a local build, a path to a
   mockup's CSS, a set of screenshots, a design file. Their word wins over every
   default below.
2. **The prototype**, by default, when `prototype_root` in
   `00_bootstrap/stack.md` is not `none`, the directory holds a buildable project,
   and it launches ([`product-roots.md`](product-roots.md)).
3. **None.** Nothing to measure from, and the operator has none to give. The values
   are then **generated by common sense**: the design system's own tokens first, the
   framework profile's conventions next, the common defaults of the stack's UI
   library last (a 240px sidebar, 16px or 24px content padding, a 44px table row).

The choice is asked once per run. An operator who names nothing gets option 2 when
it exists and option 3 otherwise.

**Always advise when values were generated.** Close the turn by saying, plainly, how
many rows across which files carry `generated`, that nobody has decided them, and
that `/inspire-bootstrap design-system` confirms them one by one. A generated value
is never written as `reference` or as a token citation: it would read as a decision
nobody made.

Record the choice in `design-system.md` § Reference, the one place every layout's
`reference` rows point at:

```markdown
## Reference

- **Reference:** the prototype at `prototype/`, run with `npm run dev`
- **Captured:** 2026-10-20
- **Widths:** 1440, 1280, 1024, 768, 390
```

With no reference the section says `none — values generated on {date}`.

## How a reference is read

1. **Record the supported range first.** `design-system.md` § Supported viewports
   names the narrowest width the product must work at, and the ranges above it,
   before any screen or layout says anything responsive. If it is absent, ask —
   phone in scope or not is a product decision, not a measurement.
2. **Capture at several widths.** 1440, 1280, 1024, 768 and 390 wide, plus the
   supported floor when it is none of those. A single desktop capture specifies one
   width and leaves every other to the implementer.
3. **Sweep to find the breakpoints.** Resize the viewport across each range and
   record the width at which the computed layout changes. Never infer a breakpoint
   from a `sm:` / `md:` / `lg:` class prefix: the stylesheet decides which rule wins,
   not the class list.
4. **Measure, don't read.** A value is the element's computed box
   (`getBoundingClientRect`, computed style) in a headless browser, never the class
   that seems to set it.
5. **Breakage is a gap, never a rule.** Clipping, overflow or overlap the reference
   shows at any width goes into the entry's `## Notes` (or a screen's
   `## Current prototype` drift, type `gap`), naming the width and the elements. The
   row proposing what should happen instead carries `undecided`.
6. **Name what you see.** Every glyph by its library and name (`lucide-folder`),
   every hover-only affordance with its touch equivalent, every component by its
   catalog entry.

## Where each observation lands

| Observation | Lands in | Source |
|---|---|---|
| a colour, font, size or spacing the whole product uses | `design-tokens.json`, cited from `design-system.md` | — (it is a token) |
| where a region sits, and at what size | a `layouts/` entry, `## Geometry` | `reference`, or `design-tokens.json` when the value is a token |
| what a region does at each range | the same entry, `## Breakpoints` | `reference` or `undecided` |
| how one value on one screen is drawn | the screen's `## Render` | — |
| what a reused piece of UI takes and renders | a `components/` entry | — |

A token observed in the reference becomes a token and its rows cite it. A
measurement only one frame uses stays a `reference` row until the design system
adopts it.
